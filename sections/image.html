1.4 · Container Image Build

Build pipeline

container/Dockerfile installs Node, Chromium/Playwright, GitHub CLI, Azure CLI, and document tooling, then bakes in claude-code and the compiled agent-runner. container/build.sh runs docker build -t nanoclaw-agent:latest . once on the host.

Local image, no registry

The image is never pushed or pulled from a registry — it is built once into the host's local Docker image cache. Every docker run from Container Runner references the same cached image by tag, so container start-up only pays the cost of creating a new writable layer, not re-downloading anything.

How containers get the image

src/config.ts defines CONTAINER_IMAGE (default nanoclaw-agent:latest, overridable via env var). container-runner.ts appends that exact tag as the final docker run argument — there is no per-request build step, just a reference to the pre-built image.

Current sharing model: one image for all groups

Today every group — Feishu, WeCom, Slack, solo chats — launches containers from the same nanoclaw-agent:latest image. Tooling, OS packages, and global npm installs are identical for every group; only mounts, env vars, and the prompt/session differ per container.

Group-specific base images: not implemented

ContainerConfig (the per-group override object) currently only exposes additionalMounts and timeout — there is no image field, and container-runner.ts always uses the single global CONTAINER_IMAGE constant. A group cannot today request extra system packages or a different runtime without changing the shared image for everyone.

What adding it would take

  1. Add an optional image field to ContainerConfig.
  2. In container-runner.ts, resolve group.containerConfig?.image ?? CONTAINER_IMAGE before pushing the docker arg.
  3. Adopt a tag convention such as nanoclaw-agent:<group>.
  4. Build group images as FROM nanoclaw-agent:latest layers so they inherit the base tooling and only add group-specific packages.
  5. Extend build.sh (or a sibling script) to build/tag those per-group images alongside the base one.
