1.3 · Session Lifecycle

Container lifetime and conversation lifetime are two related but separate clocks — this is the sequence they follow, then the edge cases where they diverge.

Normal lifecycle

  1. Container starts on demand. A group container is disposable — it starts when a message arrives and stays alive while messages keep arriving.
  2. Within the idle window, follow-ups keep flowing. New chat messages are written into the group's IPC input directory and pushed into the active Claude message stream — same container, same conversation.
  3. Container exits after ~30 minutes of output inactivity. The Claude session UUID it was using is already persisted in SQLite, and its transcript is a JSONL file under the group-specific .claude directory — both outlive the container.
  4. After exit, the next message resumes the same conversation. A fresh container launches and the saved session UUID is passed to query(resume: sessionId), picking up exactly where the transcript left off.

Edge cases

  1. Retention boundary. Inactive JSONL transcripts are cleaned after 7 days. A stale UUID cannot restore context after its transcript is deleted.
  2. Context-loss behavior. If the transcript is missing, NanoClaw recognizes the stale-session error, deletes the UUID, and the following attempt begins a new conversation instead of failing outright.
